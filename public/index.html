KATIE Guard

An agent that pays on NEAR testnet must check first: the human's policy, the counterparty, and the key it signs with. Every decision — allow, warn, block — lands in an append-only K-record that never rewrites what the agent believed.

SEEDED MOCK DATA + OFFLINE SIGNING. Every person, business, invoice and amount on this page is invented for the demo. Payments are signed offline with an ephemeral in-memory key and never broadcast — no tokens move. Testnet only; there is no mainnet path and no broadcast path in this prototype.

1 POLICY

The human sets the rules. Caps, the approval threshold, and the allowlist. Only this form can change them — pool files, chat logs and pasted text can never set policy. Saving writes a permission entry to the K-record.

Loading the current policy…

2 CHECK

Before any payment, the counterparty check returns allow, warn, or block — with reasons. Signals: the shared blocklist, NEAR testnet RPC reads (account, balance, keys, contract code), prior interactions in the K-record, and contract code changes. Account age is not scored: a plain RPC view cannot provide it.

3 PAY — GUARDED

The agent proposes a payment. Policy runs first, then the counterparty check, then the guarded signing wrapper. On block, the wrapper refuses to sign. On warn, a human must confirm. Signing uses a function-call key scoped to one demo contract — never a full-access key — and the signed transaction is shown, never broadcast.

Attack demo

Run the prompt-injection attack: the injected note in the pool tries to pay a blocklisted address and override the policy. The same guard path as a real payment runs — and blocks it. Same demo as npm run attack-demo in server/.

4 AUDIT

The K-record: everything the agent believed, was allowed to do, was trusted with, refused, and signed — by date. Old entries are never edited. When it was wrong, the correction is a new entry, and the wrong belief stays in the log. The To date always defaults to today (your local date); the From date defaults to the earliest seed entry.

The sheet changes. The notes never do.
